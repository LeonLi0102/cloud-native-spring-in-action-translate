## 8.1 使用 Reactor 和 Spring 的异步非阻塞架构

响应式宣言（www.reactivemanifesto.org）将响应式系统描述为响应式的、有韧性的、弹性的和消息驱动的。其构建松散耦合、可扩展、有韧性和经济高效的应用程序的使命与我们对云原生的定义完全兼容。

### 8.1.1 从每请求一线程到事件循环

在非响应式应用程序中，每个请求分配一个线程。在返回响应之前，线程不会用于其他任何事情。这就是每请求一线程模型。当请求处理涉及 I/O 等密集操作时，线程将阻塞，直到这些操作完成。

响应式应用程序在设计上更具可扩展性和效率。在响应式应用程序中处理请求不涉及专门分配给定线程——请求基于事件异步完成。这种称为事件循环的范式不会对应用程序的可扩展性设置硬性约束。

### 8.1.2 Project Reactor：使用 Mono 和 Flux 的响应式流

响应式 Spring 基于 Project Reactor，一个用于在 JVM 上构建异步、非阻塞应用程序的框架。Reactor 是 Reactive Streams 规范的实现。

Reactor 中的两个核心类型：

* **Mono<T>** — 表示 0 或 1 个元素的异步序列
* **Flux<T>** — 表示 0 到 N 个元素的异步序列

### 8.1.3 Spring 响应式栈

Spring 框架提供了全面的响应式支持：

* **Spring WebFlux** — 响应式 Web 框架，替代 Spring MVC
* **Spring Data R2DBC** — 响应式数据库访问
* **Spring Security Reactive** — 响应式安全
* **Spring Cloud Gateway** — 响应式 API 网关
