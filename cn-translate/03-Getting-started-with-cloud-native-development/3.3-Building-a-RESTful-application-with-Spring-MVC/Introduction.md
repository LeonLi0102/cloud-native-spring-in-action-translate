# 3.3 使用 Spring MVC 构建 RESTful 应用

如果您正在构建云原生应用，很可能您正在开发一个由多个服务（如微服务）组成的分布式系统，这些服务相互交互以完成产品的整体功能。您的应用可能被组织中另一个团队开发的服务所使用，或者您可能正在向第三方暴露其功能。无论哪种方式，任何服务间通信中都有一个基本要素：API。

15-Factor 方法论推崇 **API 优先** 模式。它鼓励您先建立服务接口，然后再着手实现。API 代表您的应用与其消费者之间的公共契约，首先定义它符合您的最佳利益。

假设您同意一个契约并首先定义了 API。在这种情况下，其他团队可以开始针对您的 API 开发他们的解决方案，以实现与您应用的集成。如果您不先开发 API，就会产生瓶颈，其他团队将不得不等待您完成应用。提前讨论 API 还能促成与利益相关者的富有成效的讨论，这可以帮助您明确应用的范围，甚至定义要实现的用户故事。

在云中，任何应用都可以是另一个应用的后端服务。采用 API 优先的心态将帮助您演进应用并使其适应未来的需求。

本节将引导您为 Catalog Service 定义一个 REST API 契约 —— 这是云原生应用最常用的服务接口模型。您将使用 Spring MVC 来实现 REST API、验证它并测试它。我还将概述一些关于如何为未来需求演进 API 的考量，这是云原生应用等高度分布式系统中的常见问题。
