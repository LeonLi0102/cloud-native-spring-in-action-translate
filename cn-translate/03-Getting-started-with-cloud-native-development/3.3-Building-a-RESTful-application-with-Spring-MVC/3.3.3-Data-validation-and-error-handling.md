### 3.3.3 数据校验和错误处理

作为一条通用规则，在保存任何数据之前，您应该始终验证内容，这既是出于数据一致性考虑，也是出于安全原因。一本没有标题的图书在我们的应用中毫无用处，而且很可能导致应用失败。

对于 `Book` 类，我们可能会考虑使用以下校验约束：

* ISBN 必须已定义且格式正确（ISBN-10 或 ISBN-13）。
* 标题必须已定义。
* 作者必须已定义。
* 价格必须已定义且大于零。

Java Bean Validation 是一种流行的规范，用于通过注解在 Java 对象上表达约束和校验规则。Spring Boot 提供了一个方便的启动器依赖，包含 Java Bean Validation API 及其实现。在您的 Catalog Service 项目的 `build.gradle` 文件中添加新依赖。添加后请记得刷新或重新导入 Gradle 依赖。

**代码清单 3.11 添加 Spring Boot Validation 依赖**

```groovy
dependencies {
 ...
 implementation 'org.springframework.boot:spring-boot-starter-validation'
}
```

现在您可以使用 Java Bean Validation API 直接在 `Book` record 的字段上以注解形式定义校验约束。

**代码清单 3.12 为每个字段定义校验约束**

```java
package com.polarbookshop.catalogservice.domain;

import javax.validation.constraints.NotBlank;
import javax.validation.constraints.NotNull;
import javax.validation.constraints.Pattern;
import javax.validation.constraints.Positive;

public record Book (
 @NotBlank(message = "The book ISBN must be defined.")
 @Pattern(
 regexp = "^([0-9]{10}|[0-9]{13})$",
 message = "The ISBN format must be valid."
 ) // 被注解的元素必须匹配指定的正则表达式（标准 ISBN 格式）
 String isbn,

 @NotBlank(message = "The book title must be defined.")
 // 被注解的元素不能为 null 且必须至少包含一个非空白字符
 String title,

 @NotBlank(message = "The book author must be defined.")
 String author,

 @NotNull(message = "The book price must be defined.")
 @Positive(message = "The book price must be greater than zero.")
 // 被注解的元素不能为 null 且必须大于零
 Double price
) {}
```

> **注意** 图书通过其 ISBN（国际标准书号）唯一标识。ISBN 过去由 10 位数字组成，但现在由 13 位组成。为简单起见，我们将仅限于通过正则表达式检查其长度以及所有元素是否为数字。

Java Bean Validation API 的注解定义了约束，但尚未强制执行。我们可以通过在 `BookController` 类中使用 `@Valid` 注解来指示 Spring 验证 `Book` 对象——只要将 `@RequestBody` 指定为方法参数时。这样，每当我们创建或更新图书时，Spring 都会运行校验并在违反任何约束时抛出错误。我们可以按如下方式更新 `BookController` 类中的 `post()` 和 `put()` 方法。

**代码清单 3.13 校验请求体中传入的图书**

```java
...
@PostMapping
@ResponseStatus(HttpStatus.CREATED)
public Book post(@Valid @RequestBody Book book) {
 return bookService.addBookToCatalog(book);
}

@PutMapping("{isbn}")
public Book put(@PathVariable String isbn, @Valid @RequestBody Book book) {
 return bookService.editBookDetails(isbn, book);
}
...
```

Spring 允许您以不同方式处理错误消息。在构建 API 时，考虑它可以抛出哪些类型的错误是很好的做法，因为它们与领域数据一样重要。当它是 REST API 时，您要确保 HTTP 响应使用最适合目的的状态码，并包含有意义的消息来帮助客户端识别问题。

当我们刚刚定义的校验约束未被满足时，会抛出 `MethodArgumentNotValidException`。如果我们尝试获取一本不存在的图书会怎样？我们之前实现的业务逻辑会抛出专用异常（`BookAlreadyExistsException` 和 `BookNotFoundException`）。所有这些异常都应该在 REST API 上下文中处理，以返回原始规范中定义的错误码。

要处理 REST API 的错误，我们可以使用标准 Java 异常，并依赖 `@RestControllerAdvice` 类来定义当给定异常被抛出时该做什么。这是一种集中化的方法，允许我们将异常处理与抛出异常的代码解耦。在 `com.polarbookshop.catalogservice.web` 包中，创建一个 `BookControllerAdvice` 类如下。

**代码清单 3.14 定义如何处理异常的通知类**

```java
package com.polarbookshop.catalogservice.web;

import java.util.HashMap;
import java.util.Map;
import com.polarbookshop.catalogservice.domain.BookAlreadyExistsException;
import com.polarbookshop.catalogservice.domain.BookNotFoundException;
import org.springframework.http.HttpStatus;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice // 标记类为集中化的异常处理器
public class BookControllerAdvice {

 @ExceptionHandler(BookNotFoundException.class)
 // 定义处理器必须执行的异常
 @ResponseStatus(HttpStatus.NOT_FOUND)
 // 定义异常抛出时创建的 HTTP 响应的状态码
 String bookNotFoundHandler(BookNotFoundException ex) {
 // 将包含在 HTTP 响应体中的消息
 return ex.getMessage();
 }

 @ExceptionHandler(BookAlreadyExistsException.class)
 @ResponseStatus(HttpStatus.UNPROCESSABLE_ENTITY)
 String bookAlreadyExistsHandler(BookAlreadyExistsException ex) {
 return ex.getMessage();
 }

 @ExceptionHandler(MethodArgumentNotValidException.class)
 // 处理当 Book 校验失败时抛出的异常
 @ResponseStatus(HttpStatus.BAD_REQUEST)
 public Map<String, String> handleValidationExceptions(
 MethodArgumentNotValidException ex) {
 var errors = new HashMap<String, String>();
 ex.getBindingResult().getAllErrors().forEach(error -> {
 String fieldName = ((FieldError) error).getField();
 String errorMessage = error.getDefaultMessage();
 // 收集有关哪些 Book 字段无效的有意义的错误消息，
 // 而不是返回空消息
 errors.put(fieldName, errorMessage);
 });
 return errors;
 }
}
```

`@RestControllerAdvice` 类中提供的映射使得以下情况成为可能：当我们尝试创建目录中已存在的图书时，获得状态码为 422（不可处理实体）的 HTTP 响应；当我们尝试读取不存在的图书时，获得状态码为 404（未找到）的响应；当 `Book` 对象中的一个或多个字段无效时，获得状态码为 400（错误请求）的响应。每个响应都将包含我们在校验约束或自定义异常中定义的有意义的消息。

构建并重新运行应用（`./gradlew bootRun`）：如果您现在尝试创建一本没有标题且 ISBN 格式错误的图书，请求将会失败。

```bash
$ http POST :9001/books author="Jon Snow" title="" isbn="123ABC456Z" \
 price=9.90
```

结果将是一个带有 "400 Bad Request" 状态码的错误消息，表示服务器无法处理 HTTP 请求，因为请求不正确。响应体包含有关请求的哪个部分不正确以及如何修复的详细消息，正如我们在代码清单 3.12 中所定义的。

```http
HTTP/1.1 400
Content-Type: application/json

{
 "isbn": "The ISBN format must be valid.",
 "title": "The book title must be defined."
}
```
