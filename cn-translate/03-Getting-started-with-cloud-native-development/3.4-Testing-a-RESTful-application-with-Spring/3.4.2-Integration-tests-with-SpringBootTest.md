### 3.4.2 使用 @SpringBootTest 进行集成测试

集成测试覆盖软件组件之间的交互，在 Spring 中它们需要定义应用上下文。`spring-boot-starter-test` 依赖还导入了 Spring Framework 和 Spring Boot 的测试工具。

Spring Boot 提供了强大的 `@SpringBootTest` 注解，您可以在测试类上使用它，在运行测试时自动引导应用上下文。用于创建上下文的配置可以根据需要进行自定义。否则，带有 `@SpringBootApplication` 注解的类将成为组件扫描和属性的配置源，包括 Spring Boot 提供的常规自动配置。

在处理 Web 应用时，您可以在模拟的 Web 环境或运行中的服务器上运行测试。您可以通过为 `@SpringBootTest` 注解提供的 `webEnvironment` 属性定义值来配置，如表 3.2 所示。

**表 3.2 Spring Boot 集成测试可以使用模拟 Web 环境或运行中的服务器来初始化**

| Web 环境选项 | 描述 |
|-------------|------|
| MOCK | 创建带有模拟 Servlet 容器的 Web 应用上下文。这是默认选项。 |
| RANDOM_PORT | 创建带有监听随机端口的 Servlet 容器的 Web 应用上下文。 |
| DEFINED_PORT | 创建带有监听通过 `server.port` 属性定义的端口的 Servlet 容器的 Web 应用上下文。 |
| NONE | 创建不带 Servlet 容器的应用上下文。 |

当使用模拟 Web 环境时，您可以依赖 `MockMvc` 对象向应用发送 HTTP 请求并检查其结果。对于有运行中服务器的环境，`TestRestTemplate` 工具允许您对运行在实际服务器上的应用执行 REST 调用。通过检查 HTTP 响应，您可以验证 API 是否按预期工作。

Spring Framework 和 Spring Boot 的最新版本扩展了测试 Web 应用的功能。现在您可以使用 `WebTestClient` 类在模拟环境和运行中服务器上测试 REST API。与 `MockMvc` 和 `TestRestTemplate` 相比，`WebTestClient` 提供了现代且流畅的 API 以及额外功能。此外，您可以将其同时用于命令式应用（如 Catalog Service）和响应式应用，优化学习和生产力。

由于 `WebTestClient` 是 Spring WebFlux 项目的一部分，您需要在 Catalog Service 项目（`build.gradle`）中添加新依赖。添加后请记得刷新或重新导入 Gradle 依赖。

**代码清单 3.16 添加 Spring Reactive Web 的测试依赖**

```groovy
dependencies {
 ...
 testImplementation 'org.springframework.boot:spring-boot-starter-webflux'
}
```

第 8 章将介绍 Spring WebFlux 和响应式应用。现在我们只对使用 `WebTestClient` 对象来测试 Catalog Service 暴露的 API 感兴趣。

在上一章中，您看到 Spring Initializr 生成了一个空的 `CatalogServiceApplicationTests` 类。让我们用集成测试来填充它。对于此设置，我们将使用 `@SpringBootTest` 注解，配置为提供完整的 Spring 应用上下文，包括通过随机端口暴露服务的运行中服务器（因为使用哪个端口并不重要）。

**代码清单 3.17 Catalog Service 的集成测试**

```java
package com.polarbookshop.catalogservice;

import com.polarbookshop.catalogservice.domain.Book;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.web.reactive.server.WebTestClient;
import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest(
 webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT
 // 加载完整的 Spring Web 应用上下文和监听随机端口的 Servlet 容器
)
class CatalogServiceApplicationTests {
 @Autowired
 private WebTestClient webTestClient; // 用于执行测试 REST 调用的工具

 @Test
 void whenPostRequestThenBookCreated() {
 var expectedBook = new Book("1231231231", "Title", "Author", 9.90);

 webTestClient.post() // 发送 HTTP POST 请求
 .uri("/books") // 将请求发送到 "/books" 端点
 .bodyValue(expectedBook) // 在请求体中添加图书
 .exchange() // 发送请求
 .expectStatus().isCreated() // 验证 HTTP 响应状态为 "201 Created"
 .expectBody(Book.class).value(actualBook -> {
 // 验证 HTTP 响应有非 null 的请求体
 assertThat(actualBook).isNotNull();
 // 验证创建的对象符合预期
 assertThat(actualBook.isbn())
 .isEqualTo(expectedBook.isbn());
 });
 }
}
```

> **注意** 您可能想知道为什么我在代码清单 3.17 中没有使用基于构造器的依赖注入，考虑到我之前说这是推荐的选择。在生产代码中使用基于字段的依赖注入已被弃用并强烈反对，但在测试类中自动装配依赖仍然是可以接受的。在其他所有场景中，我建议坚持使用基于构造器的依赖注入，原因如前所述。更多信息请参阅 Spring Framework 官方文档（[https://spring.io/projects/spring-framework](https://spring.io/projects/spring-framework)）。

然后您可以使用以下命令运行测试：

```bash
$ ./gradlew test --tests CatalogServiceApplicationTests
```

根据应用的大小，为所有集成测试加载带有自动配置的完整应用上下文可能太过重量级。Spring Boot 有一个便捷的功能（默认启用）来缓存上下文，以便它在所有用 `@SpringBootTest` 注解且配置相同的测试类中重用。有时这还不够。

测试执行时间很重要，因此 Spring Boot 完全具备通过仅加载所需的应用部分来运行集成测试的能力。让我们看看它是如何工作的。
