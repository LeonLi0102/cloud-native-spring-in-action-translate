### 3.4.1 使用 JUnit 5 进行单元测试

单元测试不感知 Spring，也不依赖任何 Spring 库。它们旨在将单个组件作为独立单元来测试其行为。单元边缘的任何依赖都被模拟（mock），以使测试与外部组件隔离。

为 Spring 应用编写单元测试与为任何其他 Java 应用编写单元测试没有区别，所以我不会详细介绍。默认情况下，任何从 Spring Initializr 创建的 Spring 项目都包含 `spring-boot-starter-test` 依赖，它会将 JUnit 5、Mockito 和 AssertJ 等测试库导入到项目中。因此，我们已经为编写单元测试做好了准备。

应用的业务逻辑通常是用单元测试覆盖的敏感区域。在 Catalog Service 应用中，单元测试的良好候选者可能是 `Book` 类的校验逻辑。校验约束使用 Java Validation API 注解定义，我们有兴趣测试它们是否被正确应用到 `Book` 类。我们可以在一个新的 `BookValidationTests` 类中检查这一点，如下面的代码清单所示。

**代码清单 3.15 验证图书校验约束的单元测试**

```java
package com.polarbookshop.catalogservice.domain;

import java.util.Set;
import javax.validation.ConstraintViolation;
import javax.validation.Validation;
import javax.validation.Validator;
import javax.validation.ValidatorFactory;
import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.Test;
import static org.assertj.core.api.Assertions.assertThat;

class BookValidationTests {
 private static Validator validator;

 @BeforeAll // 标识在类中所有测试之前执行的代码块
 static void setUp() {
 ValidatorFactory factory = Validation.buildDefaultValidatorFactory();
 validator = factory.getValidator();
 }

 @Test // 标识一个测试用例
 void whenAllFieldsCorrectThenValidationSucceeds() {
 // 创建一本具有有效 ISBN 的图书
 var book = new Book("1234567890", "Title", "Author", 9.90);
 Set<ConstraintViolation<Book>> violations = validator.validate(book);
 // 断言没有校验错误
 assertThat(violations).isEmpty();
 }

 @Test
 void whenIsbnDefinedButIncorrectThenValidationFails() {
 // 创建一本 ISBN 代码无效的图书
 var book = new Book("a234567890", "Title", "Author", 9.90);
 Set<ConstraintViolation<Book>> violations = validator.validate(book);
 assertThat(violations).hasSize(1);
 // 断言被违反的校验约束是关于不正确的 ISBN
 assertThat(violations.iterator().next().getMessage())
 .isEqualTo("The ISBN format must be valid.");
 }
}
```

然后我们可以使用以下命令运行测试：

```bash
$ ./gradlew test --tests BookValidationTests
```
