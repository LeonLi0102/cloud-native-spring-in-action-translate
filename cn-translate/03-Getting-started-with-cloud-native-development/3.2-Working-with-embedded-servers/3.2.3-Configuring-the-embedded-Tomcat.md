### 3.2.3 配置内嵌 Tomcat

Tomcat 是任何 Spring Boot Web 应用默认预配置的服务器。有时默认配置可能就足够了，但对于生产环境中的应用，您很可能需要自定义其行为以满足特定需求。

> **注意** 在传统的 Spring 应用中，您会在 `server.xml` 和 `context.xml` 等专用文件中配置 Tomcat 之类的服务器。使用 Spring Boot，您可以通过两种方式配置内嵌 Web 服务器：通过属性或通过 `WebServerFactoryCustomizer` Bean。

本节将向您展示如何通过属性配置 Tomcat。您将在下一章了解更多关于配置应用的内容。现在，只需知道您可以在项目的 `src/main/resources` 文件夹中的 `application.properties` 或 `application.yml` 文件中定义属性即可。您可以自由选择使用哪种格式：`.properties` 文件依赖键/值对，而 `.yml` 文件使用 YAML 格式。在本书中，我将使用 YAML 定义属性。Spring Initializr 默认生成一个空的 `application.properties` 文件，因此在继续之前，请记得将其扩展名从 `.properties` 改为 `.yml`。

让我们继续为 Catalog Service 应用（`catalog-service`）配置内嵌服务器。所有配置属性都将放在 `application.yml` 文件中。

#### HTTP 端口

默认情况下，内嵌服务器监听端口 8080。只要您只使用一个应用，这没问题。如果您在开发过程中运行多个 Spring 应用（云原生系统通常如此），您会希望使用 `server.port` 属性为每个应用指定不同的端口号。

**代码清单 3.1 配置 Web 服务器端口**

```yaml
server:
 port: 9001
```

#### 连接超时

`server.tomcat.connection-timeout` 属性定义了 Tomcat 在接受客户端的 TCP 连接和实际接收到 HTTP 请求之间等待的时间限制。它有助于防止拒绝服务（DoS）攻击——在这种攻击中，连接已建立，Tomcat 预留了一个线程来处理请求，但请求永远不会到来。相同的超时也用于限制在有 HTTP 请求体时读取请求体所花费的时间。

默认值是 20s（20 秒），对于标准的云原生应用来说可能太长了。在云中高度分布式系统的环境中，我们可能不想等待超过几秒钟，以免因为 Tomcat 实例挂起太久而导致级联故障。2s 左右会更好。您还可以使用 `server.tomcat.keep-alive-timeout` 属性来配置在等待新 HTTP 请求时保持连接打开的时间。

**代码清单 3.2 配置 Tomcat 超时**

```yaml
server:
 port: 9001
 tomcat:
 connection-timeout: 2s
 keep-alive-timeout: 15s
```

#### 线程池

Tomcat 有一个线程池来处理请求，遵循"一个请求一个线程"模型。可用线程数将决定可以同时处理多少个请求。您可以通过 `server.tomcat.threads.max` 属性配置请求处理线程的最大数量。您还可以定义应始终保持运行的最小线程数（`server.tomcat.threads.min-spare`），这也是启动时创建的线程数。

确定线程池的最佳配置是复杂的，没有计算它的神奇公式。资源分析、监控和大量试验通常是找到合适配置的必要手段。默认线程池最多可以增长到 200 个线程，并始终保持 10 个工作线程运行，这些是生产环境中的良好起始值。在您的本地环境中，您可能希望降低这些值以优化资源消耗，因为资源消耗随线程数线性增长。

**代码清单 3.3 配置 Tomcat 线程池**

```yaml
server:
 port: 9001
 tomcat:
 connection-timeout: 2s
 keep-alive-timeout: 15s
 threads:
 max: 50
 min-spare: 5
```
