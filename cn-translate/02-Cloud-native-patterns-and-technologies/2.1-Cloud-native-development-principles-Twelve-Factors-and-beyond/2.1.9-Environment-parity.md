### 2.1.9 环境等价

环境等价是关于让你的所有环境尽可能相似。实际上，这个要素试图解决三个差距：

**时间差距**——代码变更与其部署之间的间隔可能很长。该方法论致力于促进自动化和持续部署，以缩短从开发人员编写代码到部署到生产环境的时间。

**人员差距**——开发人员构建应用，运维人员管理其在生产环境中的部署。这个差距可以通过拥抱 DevOps 文化、改善开发人员和运维人员之间的协作来解决，以及拥抱"你构建它，你运行它"的理念。

**工具差距**——环境之间的主要差异之一是如何处理后端服务。例如，开发人员可能在本地环境中使用 H2 数据库，但在生产环境中使用 PostgreSQL。通常，所有环境都应该使用相同类型和版本的后端服务。

**环境等价实践：**

```yaml
# 使用 Docker Compose 在本地模拟生产环境
version: '3.8'
services:
 postgres:
 image: postgres:15 # 与生产环境相同版本
 environment:
 POSTGRES_DB: catalog
 POSTGRES_USER: postgres
 POSTGRES_PASSWORD: secret
 ports:
 - "5432:5432"

# 开发环境使用相同的数据库
spring:
 datasource:
 url: jdbc:postgresql://localhost:5432/catalog
 username: postgres
 password: secret
```

**容器化的好处：**

容器化是实现环境等价的最佳方式。通过将应用和所有依赖打包到容器中，你可以在任何环境中运行相同的容器，确保环境一致性。

```dockerfile
# 开发、测试、生产使用相同的容器
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY target/catalog-service-*.jar catalog-service.jar
ENTRYPOINT ["java", "-jar", "catalog-service.jar"]
```
