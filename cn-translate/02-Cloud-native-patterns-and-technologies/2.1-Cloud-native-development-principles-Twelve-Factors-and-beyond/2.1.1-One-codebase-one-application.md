### 2.1.1 一个代码库，一个应用

十五要素方法论建立了一个应用和其代码库之间的一对一映射关系，所以每个应用只有一个代码库。任何共享代码都应该在自己的代码库中作为库进行跟踪，可以作为依赖项引入，或者作为可以独立运行的服务，充当其他应用的后端服务。每个代码库可以选择在自己的版本库中进行跟踪。

部署是应用的一个运行实例。在不同环境中可以进行多个部署，它们都共享相同的应用制品。不需要为了将应用部署到特定环境而重新构建代码库：部署之间变化的任何方面（如配置）都应该在应用代码库之外。

**核心原则：**

* 每个应用对应一个代码库
* 共享代码应该作为库或独立服务
* 配置与代码分离
* 相同的制品可以部署到不同环境

**示例：**

```
# 正确：一个代码库，通过配置适配不同环境
catalog-service/
├── src/
├── build.gradle
├── application.yml # 默认配置
├── application-dev.yml # 开发环境配置
├── application-prod.yml # 生产环境配置
└── Dockerfile

# 错误：为每个环境创建单独的代码库
catalog-service-dev/ # 不要这样做
catalog-service-staging/ # 不要这样做
catalog-service-prod/ # 不要这样做
```
