### 2.1.5 配置、凭证和代码

十五要素方法论将配置定义为部署之间可能变化的所有内容。每当需要更改应用配置时，应该能够在不更改代码、不重新构建应用的情况下完成。

配置可能包括后端服务的资源句柄（如数据库或消息系统）、访问第三方 API 的凭证，以及功能标志。问问自己，如果代码库突然公开，任何凭证或特定环境的信息是否会泄露。这将告诉你是否正确地外部化了配置。

为了符合这个要素，配置不能包含在代码中或在同一代码库中跟踪。唯一的例外是默认配置，可以与应用代码库一起打包。你仍然可以使用配置文件进行其他类型的配置，但应该将它们存储在单独的仓库中。

该方法论建议将配置存储为环境变量。这样，你可以在不同环境中部署相同的应用，但根据环境配置有不同的行为。

**Spring Boot 配置外部化：**

```yaml
# application.yml - 默认配置
spring:
 datasource:
 url: ${DATABASE_URL}
 username: ${DATABASE_USERNAME}
 password: ${DATABASE_PASSWORD}

# 通过环境变量配置
DATABASE_URL=jdbc:postgresql://localhost:5432/catalog
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=secret

# 通过 Kubernetes ConfigMap 配置
apiVersion: v1
kind: ConfigMap
metadata:
 name: catalog-config
data:
 DATABASE_URL: "jdbc:postgresql://postgres:5432/catalog"
```

**敏感信息处理：**

```yaml
# 不要把敏感信息提交到代码库
# 使用 Kubernetes Secrets
apiVersion: v1
kind: Secret
metadata:
 name: catalog-secrets
type: Opaque
data:
 DATABASE_USERNAME: cG9zdGdyZXM= # base64 编码
 DATABASE_PASSWORD: c2VjcmV0 # base64 编码
```
