### 2.1.12 无状态进程

在上一章中，我们了解到高可扩展性是迁移到云的原因之一。为了确保可扩展性，我们将应用设计为无状态进程，并采用无共享架构：不同应用实例之间不应该共享状态。问问自己，如果应用的一个实例被销毁并重建，是否会丢失任何数据。如果答案是肯定的，那么你的应用就不是无状态的。

无论如何，我们总是需要保存一些状态，否则我们的应用在大多数情况下将毫无用处。因此，我们将应用设计为无状态的，然后只在特定的有状态服务（如数据存储）中处理状态。换句话说，无状态应用将状态管理和存储委托给后端服务。

**无状态设计原则：**

* 实例之间不共享会话状态
* 状态存储在外部服务中（数据库、缓存）
* 任何请求可以被任何实例处理
* 实例可以随时创建和销毁

**会话状态外部化：**

```java
// 错误：将会话状态存储在内存中
@Controller
public class OrderController {
 @Autowired
 private HttpSession session;
 
 @GetMapping("/cart")
 public Cart getCart() {
 // 这样会话状态绑定到特定实例
 return (Cart) session.getAttribute("cart");
 }
}

// 正确：将会话状态存储在 Redis 中
@Controller
public class OrderController {
 @Autowired
 private ReactiveRedisTemplate<String, Cart> redisTemplate;
 
 @GetMapping("/cart")
 public Mono<Cart> getCart(String sessionId) {
 // 会话状态存储在 Redis，任何实例都可以访问
 return redisTemplate.opsForValue().get("cart:" + sessionId);
 }
}
```

**Spring Session 外部化会话：**

```yaml
# 使用 Redis 存储会话
spring:
 session:
 store-type: redis
 redis:
 namespace: myapp
 flush-mode: on_save
```
