### 2.1.6 日志

云原生应用不关心日志的路由和存储。应用应该将日志输出到标准输出，将日志视为按时间顺序发出的事件流。日志存储和轮转不再是应用的责任。外部工具（日志聚合器）将获取、收集日志并使其可供检查。

**核心原则：**

* 应用只负责生成日志
* 日志输出到 stdout/stderr
* 不要在应用中处理日志存储
* 使用结构化日志格式

**Spring Boot 日志配置：**

```yaml
logging:
 pattern:
 console: "%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n"
 level:
 root: INFO
 com.polarbookshop: DEBUG
```

**日志聚合架构：**

```
应用容器 → stdout → Fluent Bit → Loki → Grafana
 ↓
 Elasticsearch → Kibana
```

**结构化日志示例：**

```java
// 使用 Logback 的 JSON 格式
log.info("Order created, orderId={}, userId={}, amount={}", 
 orderId, userId, amount);

// 输出 JSON 格式日志
{
 "timestamp": "2022-07-07T17:21:00.000Z",
 "level": "INFO",
 "thread": "http-nio-8080-exec-1",
 "logger": "com.polarbookshop.order.OrderService",
 "message": "Order created, orderId=12345, userId=67890, amount=29.99"
}
```
