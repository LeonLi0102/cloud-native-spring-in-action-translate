### 2.1.11 端口绑定

遵循十五要素方法论的应用应该是自包含的，并通过端口绑定导出其服务。在生产环境中，可能会有一些路由服务将请求从公共端点转换到内部端口绑定的服务。

如果应用不依赖执行环境中的外部服务器，那么它就是自包含的。Java Web 应用可能运行在 Tomcat、Jetty 或 Undertow 等服务器容器内。相比之下，云原生应用不需要环境中有可用的 Tomcat 服务器；它会像管理任何其他依赖一样自己管理服务器。例如，Spring Boot 允许你使用嵌入式服务器：应用将包含服务器，而不是依赖执行环境中可用的服务器。这种方法的结果之一是应用和服务器之间始终是一对一的映射，不像传统方法中多个应用部署到同一服务器。

**Spring Boot 端口绑定：**

```yaml
# application.yml
server:
 port: 8080

# 通过环境变量覆盖
SERVER_PORT=8081

# Kubernetes Service 端口绑定
apiVersion: v1
kind: Service
metadata:
 name: catalog-service
spec:
 selector:
 app: catalog-service
 ports:
 - port: 80 # 服务端口
 targetPort: 8080 # 容器端口
 type: LoadBalancer
```

**自包含应用的好处：**

* 不依赖外部服务器
* 可以独立部署和扩展
* 简化容器化
* 便于本地开发和测试

**Spring Boot 嵌入式服务器：**

```groovy
// build.gradle
dependencies {
 // 默认使用 Tomcat
 implementation 'org.springframework.boot:spring-boot-starter-web'
 
 // 或使用 Netty（响应式）
 implementation 'org.springframework.boot:spring-boot-starter-webflux'
}
```
