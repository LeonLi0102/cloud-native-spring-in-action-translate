### 2.1.2 API 优先

云原生系统通常由多个通过 API 通信的服务组成。在设计云原生应用时采用 API 优先的方法，鼓励你思考如何将其融入分布式系统，并促进跨团队的工作分配。

通过先设计 API，将该应用作为后端服务的其他团队可以针对该 API 创建他们的解决方案。通过预先设计契约，与其他系统的集成将更加健壮，并且可以作为部署流水线的一部分进行测试。在内部，API 的实现可以更改，而不会影响依赖它的其他应用（和团队）。

**API 优先的好处：**

* **团队并行开发**——前端和后端团队可以并行工作
* **契约明确**——减少沟通成本和误解
* **易于测试**——API 契约可以用于自动化测试
* **文档自动生成**——使用 OpenAPI 可以自动生成文档

**示例：OpenAPI 定义**

```yaml
openapi: 3.0.0
info:
 title: Catalog Service API
 version: 1.0.0
paths:
 /api/catalog:
 get:
 summary: 获取所有书籍
 responses:
 '200':
 description: 成功
 content:
 application/json:
 schema:
 type: array
 items:
 $ref: '#/components/schemas/Book'
components:
 schemas:
 Book:
 type: object
 properties:
 id:
 type: integer
 title:
 type: string
 author:
 type: string
```
