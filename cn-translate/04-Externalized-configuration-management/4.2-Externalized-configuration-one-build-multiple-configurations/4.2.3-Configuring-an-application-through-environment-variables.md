### 4.2.3 通过环境变量配置应用程序

操作系统中定义的环境变量通常用于外部化配置，它们是 15 要素方法论推荐的选项。环境变量的优势之一是每个操作系统都支持它们，使其在任何环境中都具有可移植性。此外，大多数编程语言都提供了访问环境变量的功能。例如，在 Java 中，您可以通过调用 `System.getenv()` 方法来实现。

在 Spring 中，您不需要显式地从周围系统读取环境变量。Spring 在启动阶段自动读取它们，并将它们添加到 Spring Environment 对象中，使其像任何其他属性一样可访问。例如，如果您在一个定义了 `MY_ENV_VAR` 变量的环境中运行 Spring 应用程序，您可以通过 Environment 接口或使用 `@Value` 注解访问其值。

在此基础上，Spring Boot 扩展了 Spring 框架的功能，允许您使用环境变量自动覆盖 Spring 属性。对于命令行参数和 JVM 系统属性，您使用了与 Spring 属性相同的命名约定。然而，环境变量有一些由操作系统决定的命名约束。例如，在 Linux 上，常见语法是使用全大写字母并用下划线分隔单词。

您可以将 Spring 属性键转换为环境变量，方法是将所有字母大写，并将任何点或破折号替换为下划线。Spring Boot 会将其正确映射到内部语法。例如，`POLAR_GREETING` 环境变量被识别为 `polar.greeting` 属性。此功能称为宽松绑定（relaxed binding）。

在 Catalog Service 应用程序中，您可以使用以下命令覆盖 `polar.greeting` 属性：

```bash
$ POLAR_GREETING="Welcome to the catalog from ENV" \
 java -jar build/libs/catalog-service-0.0.1-SNAPSHOT.jar
```

> 提示：在 Windows 上，您可以通过在 PowerShell 控制台中运行 `$env:POLAR_GREETING="Welcome to the catalog from ENV"; java -jar build/libs/catalog-service-0.0.1-SNAPSHOT.jar` 来实现相同的结果。

在 Catalog Service 的启动阶段，Spring Boot 将读取周围环境中定义的变量，识别出 `POLAR_GREETING` 可以映射到 `polar.greeting` 属性，并将其值存储在 Spring Environment 对象中，覆盖 `application.yml` 中定义的值。结果将是以下内容：

```bash
$ http :9001/
Welcome to the catalog from ENV
```

测试完应用程序后，使用 Ctrl-C 停止进程。如果您从 Windows PowerShell 运行了应用程序，请记得使用 `Remove-Item Env:\POLAR_GREETING` 取消设置环境变量。

当您使用环境变量存储配置数据时，不需要更改运行应用程序的命令（就像使用 CLI 参数和 JVM 属性时那样）。Spring 会自动从部署上下文中读取环境变量。这种方法比使用 CLI 参数或 JVM 系统属性更不容易出错和脆弱。

> 注意：您可以使用环境变量定义依赖于部署应用程序的基础设施或平台的配置值，例如 profiles、端口号、IP 地址和 URL。

环境变量在虚拟机、OCI 容器和 Kubernetes 集群上无缝工作。然而，它们可能不够用。在下一节中，我将介绍影响环境变量的一些问题以及 Spring Cloud Config 如何帮助解决这些问题。
