### 4.4.2 使配置客户端更具韧性

当与配置服务器的集成不是可选的时候，如果应用程序无法联系到配置服务器，它将无法启动。即使服务器正在运行，由于交互的分布式特性，您仍可能遇到问题。因此，定义一些超时时间以使应用程序更快失败是一个好主意。您可以使用 `spring.cloud.config.request-connect-timeout` 属性来控制与配置服务器建立连接的时间限制。`spring.cloud.config.request-read-timeout` 属性允许您限制从服务器读取配置数据的时间。

打开 Catalog Service 项目的 `application.yml` 文件并应用以下配置，使与 Config Service 的交互更具韧性。再次强调，设置超时没有通用规则。根据您的架构和基础设施特性，您可能需要调整这些值。

**代码清单 4.16 使 Spring Cloud Config Client 更具韧性**

```yaml
spring:
 application:
 name: catalog-service
 config:
 import: "optional:configserver:"
 cloud:
 config:
 uri: http://localhost:8888
 request-connect-timeout: 5000 # 等待连接配置服务器的超时时间（毫秒）
 request-read-timeout: 5000 # 等待从配置服务器读取配置数据的超时时间（毫秒）
```

即使 Config Service 已复制，当 Catalog Service 等客户端应用程序启动时，它仍有可能暂时不可用。在这种情况下，您可以利用重试模式，配置应用程序在放弃和失败之前再次尝试连接配置服务器。Spring Cloud Config Client 的重试实现基于 Spring Retry，因此您需要在 Catalog Service 项目的 `build.gradle` 文件中添加新依赖。添加后记得刷新或重新导入 Gradle 依赖。

**代码清单 4.17 在 Catalog Service 中添加 Spring Retry 依赖**

```groovy
dependencies {
 ...
 implementation 'org.springframework.retry:spring-retry'
}
```

在第 8 章中，我将详细解释重试模式。现在，我将向您展示如何配置 Catalog Service，使其在失败之前重试连接 Config Service 几次（`spring.cloud.config.retry.max-attempts`）。每次连接尝试都根据指数退避策略延迟，计算方式为当前延迟乘以 `spring.cloud.config.retry.multiplier` 属性的值。初始延迟由 `spring.cloud.config.retry.initial-interval` 配置，每次延迟不能超过 `spring.cloud.config.retry.max-interval` 的值。

您可以将重试配置添加到 Catalog Service 项目的 `application.yml` 文件中。

**代码清单 4.18 将重试模式应用于 Spring Cloud Config Client**

```yaml
spring:
 application:
 name: catalog-service
 config:
 import: "optional:configserver:"
 cloud:
 config:
 uri: http://localhost:8888
 request-connect-timeout: 5000
 request-read-timeout: 5000
 fail-fast: true # 使连接配置服务器的失败变为致命的
 retry:
 max-attempts: 6 # 最大尝试次数
 initial-interval: 1000 # 退避的初始重试间隔（毫秒）
 max-interval: 2000 # 退避的最大重试间隔（毫秒）
 multiplier: 1.1 # 计算下一个间隔的乘数
```

重试行为仅在 `spring.cloud.config.fail-fast` 属性设置为 `true` 时启用。如果配置服务器宕机，您可能不希望在本地环境中重试，特别是考虑到我们已将其设为可选的后端服务。可以随意测试配置服务器宕机时的重试行为，但如果您想在本地环境中保持可选，请记得将 `fail-fast` 属性设回 `false`。在生产环境中，您可以使用本章介绍的策略之一将其设为 `true`。测试完应用程序后，使用 Ctrl-C 停止两者。
