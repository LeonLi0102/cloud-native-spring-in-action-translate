### 4.3.1 使用 Git 存储配置数据

配置服务器将负责向 Spring 应用程序提供配置数据。但在设置之前，我们需要一种方式来存储和跟踪这些数据。Spring Cloud Config Server 与许多不同的后端解决方案集成以存储配置数据。其中最常见的选择之一是 Git 仓库。

首先，创建一个新的 `config-repo` Git 仓库（最终结果可以参考 Chapter04/04-end/config-repo）。仓库可以是本地的或远程的，但对于本示例，我建议在 GitHub 上初始化一个远程仓库，就像您为应用程序仓库所做的那样。我使用 `main` 作为默认分支名称。

在配置仓库中，您可以直接以 Spring 格式存储属性，如 `*.properties` 或 `*.yml` 文件。

继续以 Catalog Service 为例，让我们为欢迎消息定义一个外部属性。导航到 `config-repo` 文件夹并创建一个 `catalog-service.yml` 文件。然后为 Catalog Service 使用的 `polar.greeting` 属性定义一个值。

**代码清单 4.8 定义使用配置服务器时的消息**

```yaml
polar:
 greeting: "Welcome to the catalog from the config server"
```

接下来，创建一个 `catalog-service-prod.yml` 文件，并为 `polar.greeting` 属性定义一个仅在 `prod` profile 激活时使用的不同值。

**代码清单 4.9 定义 prod profile 激活时的消息**

```yaml
polar:
 greeting: "Welcome to the production catalog from the config server"
```

最后，提交并将更改推送到远程仓库。

Spring Cloud Config 如何为每个应用程序解析正确的配置数据？您应该如何组织仓库以托管多个应用程序的属性？该库依赖三个参数来标识使用哪个属性文件来配置特定应用程序：

* `{application}` — 由 `spring.application.name` 属性定义的应用程序名称。
* `{profile}` — 由 `spring.profiles.active` 属性定义的活动 profile 之一。
* `{label}` — 由特定配置数据仓库定义的区分符。对于 Git，它可以是标签、分支名称或提交 ID。它对于标识一组版本化的配置文件很有用。

根据您的需要，您可以使用不同的组合来组织文件夹结构，例如：

```
/{application}/application-{profile}.yml
/{application}/application.yml
/{application}-{profile}.yml
/{application}.yml
/application-{profile}.yml
/application.yml
```

对于每个应用程序，您可以使用以应用程序本身命名并放在根文件夹中的属性文件（例如 `/catalog-service.yml` 或 `/catalog-service-prod.yml`），或使用默认命名并将它们放在以应用程序命名的子文件夹中（例如 `/catalog-service/application.yml` 或 `/catalog-service/application-prod.yml`）。

您还可以将 `application.yml` 或 `application-{profile}.yml` 文件放在根文件夹中，为所有应用程序定义默认值。当没有更具体的属性源时，它们可以用作回退。Spring Cloud Config Server 将始终从最具体的路径返回属性，使用应用程序名称、活动 profile 和 Git 标签。

当使用 Git 作为配置服务器的后端时，标签概念特别有趣。例如，您可以为不同环境创建配置仓库的长期分支，或在测试特定功能时创建短期分支。Spring Cloud Config Server 可以使用标签信息从正确的 Git 分支、标签或提交 ID 返回正确的配置数据。

现在您已经有了一个用于配置数据的 Git 仓库，是时候设置配置服务器来管理它们了。
