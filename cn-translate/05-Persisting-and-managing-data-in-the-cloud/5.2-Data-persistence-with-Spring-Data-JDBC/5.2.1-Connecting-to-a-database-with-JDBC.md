### 5.2.1 使用 JDBC 连接数据库

让我们开始为 Catalog Service 应用程序实现数据持久化层。至少需要导入要使用的特定数据库的 Spring Data 模块，如果需要，还要导入数据库驱动程序。由于 Spring Data JDBC 支持不同的关系型数据库，您需要显式声明要使用的特定数据库驱动程序的依赖。

在 Catalog Service 项目的 build.gradle 文件中添加两个新依赖。添加新依赖后记得刷新或重新导入 Gradle 依赖。

**代码清单 5.1 在 Catalog Service 中添加 Spring Data JDBC 依赖**

```groovy
dependencies {
 ...
 implementation 'org.springframework.boot:spring-boot-starter-data-jdbc'
 runtimeOnly 'org.postgresql:postgresql'
}
```

这些是主要依赖：

* **Spring Data JDBC**（org.springframework.boot:spring-boot-starter-data-jdbc）— 提供使用 Spring Data 和 JDBC 在关系型数据库中持久化数据所需的库。
* **PostgreSQL**（org.postgresql:postgresql）— 提供允许应用程序连接到 PostgreSQL 数据库的 JDBC 驱动程序。

PostgreSQL 数据库是 Catalog Service 应用程序的后端服务。根据 15 要素方法论，它应该作为附加资源处理。附加通过资源绑定完成，对于 PostgreSQL，包括以下内容：

* 定义使用哪个驱动程序、在哪里找到数据库服务器以及将应用程序连接到哪个数据库的 URL
* 与指定数据库建立连接的用户名和密码

借助 Spring Boot，您可以将这些值作为配置属性提供。这意味着您可以通过更改资源绑定的值轻松替换附加的数据库。

打开 Catalog Service 项目的 application.yml 文件，添加配置与 PostgreSQL 连接的属性。这些值是您之前在创建 PostgreSQL 容器时定义的环境变量。

**代码清单 5.2 使用 JDBC 配置数据库连接**

```yaml
spring:
 datasource:
 username: user
 password: password
 url: jdbc:postgresql://localhost:5432/polardb_catalog
```

打开和关闭数据库连接是相对昂贵的操作，因此您不希望每次应用程序访问数据时都这样做。解决方案是连接池：应用程序与数据库建立多个连接并重用它们，而不是为每个数据访问操作创建新连接。这是相当大的性能优化。

Spring Boot 使用 HikariCP 进行连接池管理，您可以从 application.yml 文件进行配置。您应该至少配置连接超时（spring.datasource.hikari.connection-timeout）和池中最大连接数（spring.datasource.hikari.maximum-pool-size），因为这两个都会影响应用程序的韧性和性能。

**代码清单 5.3 配置连接池与数据库交互**

```yaml
spring:
 datasource:
 username: user
 password: password
 url: jdbc:postgresql://localhost:5432/polardb_catalog
 hikari:
 connection-timeout: 2000
 maximum-pool-size: 5
```

现在您已经将 Spring Boot 应用程序连接到 PostgreSQL 数据库，可以继续定义要持久化的数据。
