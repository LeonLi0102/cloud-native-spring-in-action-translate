### 5.1.2 以容器方式运行 PostgreSQL

对于 Catalog Service 应用程序，我们将使用关系型数据库 PostgreSQL 来存储目录中的图书数据（[www.postgresql.org](http://www.postgresql.org)）。PostgreSQL 是一个流行的开源数据库，具有强大的可靠性、健壮性和性能，支持关系型和非关系型数据。大多数云提供商将 PostgreSQL 作为托管服务提供，使您无需自行处理高可用性、韧性和持久化存储等问题。例如 Azure Database for PostgreSQL、Amazon RDS for PostgreSQL、Google Cloud SQL for PostgreSQL、阿里云 ApsaraDB RDS for PostgreSQL 和 DigitalOcean PostgreSQL。

在本书后面，我们将把 Polar Bookshop 系统部署到由云提供商管理的 Kubernetes 集群中，届时将展示如何使用他们提供的托管 PostgreSQL 服务。您需要确保环境一致性，这是 15 要素方法论推荐的做法，因此在开发中也将使用 PostgreSQL。Docker 使在本地运行数据库变得前所未有地简单，下面将展示如何在本地机器上以容器方式运行 PostgreSQL。

在第 2 章中，您已经使用 Catalog Service 应用程序初次尝试了 Docker。以容器方式运行 PostgreSQL 没有什么不同。确保 Docker Engine 正在运行，打开终端窗口，执行以下命令：

```bash
$ docker run -d \
 --name polar-postgres \
 -e POSTGRES_USER=user \
 -e POSTGRES_PASSWORD=password \
 -e POSTGRES_DB=polardb_catalog \
 -p 5432:5432 \
 postgres:14.4
```

与运行 Catalog Service 容器相比，您会注意到几个新元素。首先，从中运行容器的 Docker 镜像（postgres:14.4）不是您创建的——它是从 Docker Hub 容器注册表拉取的（安装 Docker 时默认配置）。

第二个新元素是将环境变量作为参数传递给容器。PostgreSQL 接受一些环境变量，这些变量在容器创建期间用于配置数据库。

> 注意：本书不介绍如何在 Docker 中配置存储（卷）。这意味着保存在本地 PostgreSQL 容器中的所有数据在删除容器后都会丢失。虽然这与本章主题有些矛盾，但在生产环境中，任何存储相关的问题都将由云提供商处理，您无需自己处理。如果需要为本地容器添加持久化存储，可以参阅 Docker 官方文档中关于使用卷的说明（[https://docs.docker.com](https://docs.docker.com)）。

下一节将展示如何使用 Spring Data JDBC 和 PostgreSQL 为 Spring Boot 应用程序添加数据持久化功能。

> 注意：如果需要，可以使用 `docker stop polar-postgres` 停止容器，使用 `docker start polar-postgres` 重新启动。如果想重新开始，可以使用 `docker rm -fv polar-postgres` 删除容器，然后使用之前的 `docker run` 命令重新创建。
