## 15.2 GitOps

GitOps 是一种操作模型，其中 Git 仓库作为基础设施和应用程序配置的单一真相来源。

### 15.2.1 GitOps 核心原则

1. **声明式配置** — 系统的期望状态以声明方式描述
2. **版本化和不可变** — 所有配置都存储在 Git 中，具有完整的历史记录
3. **自动拉取** — 软件代理自动拉取配置变更
4. **持续调和** — 系统持续比较期望状态和实际状态

### 15.2.2 使用 Argo CD

Argo CD 是一个流行的 GitOps 工具，用于 Kubernetes：

```yaml
# argocd-application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: catalog-service
  namespace: argocd
spec:
  project: default
  source:
    repoURL: https://github.com/your-username/k8s-config.git
    targetRevision: main
    path: catalog-service
  destination:
    server: https://kubernetes.default.svc
    namespace: polar-bookshop
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

### 15.2.3 GitOps 工作流程

1. 开发人员修改代码并推送到 Git
2. CI 流水线构建和测试代码
3. CI 创建新的容器镜像
4. CI 更新配置仓库中的镜像标签
5. Argo CD 检测到配置变更
6. Argo CD 将变更同步到 Kubernetes 集群

GitOps 使得部署更加可靠和可审计。
