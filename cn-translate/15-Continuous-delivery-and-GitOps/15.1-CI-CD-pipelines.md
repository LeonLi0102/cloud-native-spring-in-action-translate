## 15.1 CI/CD 流水线

持续集成（CI）和持续交付（CD）是现代软件开发的核心实践，帮助团队快速、可靠地交付软件。

### 15.1.1 理解 CI/CD

* **持续集成（CI）** — 开发人员频繁地将代码更改集成到共享仓库中，每次集成都通过自动化构建进行验证
* **持续交付（CD）** — 自动化将通过所有测试阶段的应用程序部署到生产环境
* **持续部署** — 自动化将通过所有测试阶段的应用程序部署到生产环境，无需人工干预

### 15.1.2 GitHub Actions 配置

```yaml
name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up JDK 17
        uses: actions/setup-java@v3
        with:
          java-version: '17'
          distribution: 'temurin'
      - name: Build with Gradle
        run: ./gradlew build
      - name: Run tests
        run: ./gradlew test
      - name: Build container image
        run: ./gradlew bootBuildImage
  
  deploy:
    needs: build-and-test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Deploy to Kubernetes
        run: kubectl apply -f kubernetes/
```

### 15.1.3 流水线阶段

1. **编译** — 检查代码是否能编译
2. **单元测试** — 验证单个组件
3. **集成测试** — 验证组件之间的交互
4. **安全扫描** — 检查漏洞
5. **构建镜像** — 创建容器镜像
6. **部署** — 部署到目标环境
7. **冒烟测试** — 验证部署是否成功

CI/CD 流水线提高了软件交付的速度和质量。
