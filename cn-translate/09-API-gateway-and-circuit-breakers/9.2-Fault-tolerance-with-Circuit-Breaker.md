## 9.2 使用 Circuit Breaker 和 Resilience4j 实现容错

在分布式系统中，服务之间的调用可能会失败。断路器模式是一种保护机制，当失败率超过阈值时，阻止进一步调用，从而保护下游服务和系统资源。

### 9.2.1 理解断路器模式

断路器有三种状态：

* **关闭（Closed）** — 正常状态，请求正常通过
* **打开（Open）** — 故障状态，所有请求立即失败
* **半开（Half-Open）** — 恢复状态，允许部分请求通过以测试服务是否恢复

### 9.2.2 配置断路器

在 Gateway 中配置断路器：

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: catalog-route
          uri: http://localhost:9001
          predicates:
            - Path=/books/**
          filters:
            - name: CircuitBreaker
              args:
                name: catalogService
                fallbackUri: forward:/fallback/catalog
```

### 9.2.3 实现重试和超时

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: catalog-route
          uri: http://localhost:9001
          predicates:
            - Path=/books/**
          filters:
            - name: Retry
              args:
                retries: 3
                statuses: BAD_GATEWAY
                methods: GET
      httpclient:
        connect-timeout: 5000
        response-timeout: 10s
```

### 9.2.4 使用 Resilience4j 配置

```yaml
resilience4j:
  circuitbreaker:
    instances:
      catalogService:
        slidingWindowSize: 10
        failureRateThreshold: 50
        waitDurationInOpenState: 10s
        permittedNumberOfCallsInHalfOpenState: 3
  retry:
    instances:
      catalogService:
        maxAttempts: 3
        waitDuration: 500ms
```
