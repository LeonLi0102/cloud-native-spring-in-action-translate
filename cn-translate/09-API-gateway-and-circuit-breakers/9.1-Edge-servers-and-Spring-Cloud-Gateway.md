## 9.1 边缘服务器和 Spring Cloud Gateway

由于 API 网关是系统的入口点，它也是处理横切关注点（如安全性、监控和韧性）的绝佳位置。边缘服务器是系统边缘的应用程序，实现 API 网关和横切关注点等功能。

### 9.1.1 使用 Spring Cloud Gateway 启动边缘服务器

Polar Bookshop 系统需要一个边缘服务器将流量路由到内部 API 并解决几个横切关注点。您可以从 Spring Initializr（https://start.spring.io）初始化新的 Edge Service 项目。

依赖配置：

```groovy
dependencies {
    implementation 'org.springframework.cloud:spring-cloud-starter-gateway'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}
```

配置 Netty 服务器和优雅关闭：

```yaml
server:
  port: 9000
  netty:
    connection-timeout: 2s
    idle-timeout: 15s
  shutdown: graceful

spring:
  application:
    name: edge-service
  lifecycle:
    timeout-per-shutdown-phase: 15s
```

### 9.1.2 定义路由和谓词

Spring Cloud Gateway 提供三个主要构建块：

* **路由（Route）** — 由唯一 ID、谓词集合、URI 和过滤器集合标识
* **谓词（Predicate）** — 匹配 HTTP 请求的任何内容，包括路径、主机、头、查询参数、cookie 和主体
* **过滤器（Filter）** — 在转发请求之前或之后修改 HTTP 请求或响应

配置路由：

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: catalog-route
          uri: ${CATALOG_SERVICE_URL:http://localhost:9001}/books
          predicates:
            - Path=/books/**
        - id: order-route
          uri: ${ORDER_SERVICE_URL:http://localhost:9002}/orders
          predicates:
            - Path=/orders/**
```

### 9.1.3 使用过滤器

过滤器可以在请求转发到下游服务之前或之后修改请求：

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: catalog-route
          uri: http://localhost:9001
          predicates:
            - Path=/books/**
          filters:
            - AddRequestHeader=X-Source, gateway
            - StripPrefix=1
            - name: Retry
              args:
                retries: 3
                statuses: BAD_GATEWAY
                methods: GET
```
