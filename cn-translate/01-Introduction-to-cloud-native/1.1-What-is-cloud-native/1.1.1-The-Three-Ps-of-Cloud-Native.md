### 1.1.1 云原生的 3 个 P

专门为云设计的应用程序到底意味着什么呢？云原生计算基金会（CNCF）在其云原生定义中回答了这个问题：

> _云原生技术使组织能够在现代的、动态的环境中构建和运行可扩展的应用程序，例如公有云、私有云和混合云。容器、服务网格、微服务、不可变基础设施和声明式 API 就是这种方法的典型示例。_
>
> _这些技术使松散耦合的系统具有弹性、可管理和可观测性。与强大的自动化相结合，它们允许工程师以最少的工作量，频繁且可预测地进行高影响力的重大变更。_

根据这个定义，我确定了三个要点，我称之为云原生的 3 个 P：

* **平台（Platforms）**——云原生应用程序运行在基于动态、分布式环境的平台上：云（公有云、私有云或混合云）。
* **特性（Properties）**——云原生应用程序被设计为可扩展的、松散耦合的、有弹性的、可管理和可观测的。
* **实践（Practices）**——围绕云原生应用程序的实践包括强大的自动化、持续交付和 DevOps。

#### 位置（Place）

云原生应用程序运行在现代的、动态的环境中：云。公有云由云服务提供商拥有和运营，通过互联网向公众提供计算资源（如虚拟机、存储和数据库）的访问。私有云由单个组织拥有和运营，仅供内部使用。混合云结合了公有云和私有云，允许数据和应用程序在它们之间共享。

#### 特性（Properties）

云原生应用程序具有以下特性：

* **可扩展性（Scalability）**——能够动态增加或减少资源以应对工作负载变化。
* **松散耦合（Loose coupling）**——组件之间相互了解的程度最小化，可以独立部署和更新。
* **弹性（Resilience）**——在面对故障时能够维持服务水平。
* **可管理性（Manageability）**——可以从外部进行控制：更新、配置、部署。
* **可观测性（Observability）**——可以从外部推断系统的内部状态。

#### 实践（Practices）

支持云原生的实践包括：

* **自动化（Automation）**——建立可重复、高效和可靠的系统。
* **持续交付（Continuous delivery）**——更好、更快地交付软件。
* **DevOps**——不同角色之间的协作文化，打破开发和运维之间的壁垒。

> **什么是云原生计算基金会？**
>
> 云原生计算基金会（CNCF）是 Linux 基金会的一部分，致力于构建可持续的生态系统，促进社区支持云原生开源软件的增长和健康。CNCF 主办了许多云原生技术和项目，以支持云的可移植性，同时避免供应商锁定。如果你想了解云原生方面的项目，建议查看 CNCF 云原生全景图。

在接下来的小节中，我们将进一步研究这些概念。不过，首先需要注意的是，云原生的定义与任何特定的实现或技术细节无关。CNCF 在定义中提到的容器和微服务等，都只是例子。最常见的误解是，迁移到云时必须采用微服务架构并构建容器。然而事实并非如此。Fremantle 在 2010 年的文章就是证明——他没有提到这些技术，因为当时它们都不存在。然而，他所描述的应用程序不仅仍然被认为是云原生的，而且还符合 CNCF 八年后给出的定义。
