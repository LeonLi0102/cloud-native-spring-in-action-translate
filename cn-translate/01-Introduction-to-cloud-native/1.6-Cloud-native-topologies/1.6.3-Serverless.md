### 1.6.3 Serverless

Serverless 是一种云计算模型，开发者只需要关注代码，而不需要管理服务器、容器或基础设施。云平台负责处理所有底层基础设施的管理、扩展和维护。

**Serverless 的核心概念：**

* **函数即服务（FaaS）**——将代码部署为函数，按执行次数和时间计费。
* **后端即服务（BaaS）**——使用云提供商的托管服务（数据库、认证、存储等）。
* **按需付费**——只为实际执行的代码付费，空闲时不收费。
* **自动扩展**——根据请求量自动扩展，包括缩放到零。

**Serverless 平台：**

| 平台 | 提供商 | 特点 |
|------|--------|------|
| AWS Lambda | AWS | 最早、最成熟的 FaaS 平台 |
| Azure Functions | Microsoft | 与 Azure 深度集成 |
| Google Cloud Functions | Google | 与 GCP 服务集成 |
| OpenFaaS | 开源 | 可以在任何 Kubernetes 集群上运行 |
| Knative | 开源 | 基于 Kubernetes 的 Serverless 平台 |

**Serverless 示例（AWS Lambda）：**

```java
// 使用 Spring Cloud Function
@Bean
public Function<String, String>uppercase() {
 return value -> value.toUpperCase();
}

// 部署到 AWS Lambda
// 使用 AWS Serverless Java Container
```

```yaml
# serverless.yml (Serverless Framework)
service: catalog-function

provider:
 name: aws
 runtime: java17
 memorySize: 512
 timeout: 30

functions:
 catalog:
 handler: org.springframework.cloud.function.adapter.aws.SpringBootStreamHandler
 events:
 - http:
 path: /catalog
 method: get
```

**Serverless 的优势：**

* **零运维**——不需要管理服务器、操作系统或运行时。
* **按需付费**——空闲时不收费，成本与使用量成正比。
* **自动扩展**——从零扩展到数千个并发实例。
* **快速上市**——专注于业务逻辑，快速迭代。

**Serverless 的限制：**

* **冷启动**——长时间不使用的函数可能需要几秒到几十秒才能启动。
* **执行时间限制**——函数执行时间有上限（如 AWS Lambda 最长 15 分钟）。
* **状态管理**——函数是无状态的，需要外部服务管理状态。
* **供应商锁定**——迁移到其他平台可能需要重写代码。
* **调试困难**——分布式调试比传统应用更复杂。

**适用场景：**

* 事件驱动的工作负载
* API 后端
* 数据处理管道
* 定时任务
* 低流量或突发流量的应用

Serverless 不是银弹，但在合适的场景下，它可以显著降低成本和运维复杂性。
