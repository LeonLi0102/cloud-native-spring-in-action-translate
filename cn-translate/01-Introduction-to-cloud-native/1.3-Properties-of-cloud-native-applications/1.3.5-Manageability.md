### 1.3.5 可管理性

可管理性是从外部控制系统的能力，包括更新、配置和部署。在云原生环境中，应用程序通常由许多微服务组成，部署在多个环境中（开发、测试、生产）。可管理性确保这些操作可以高效、安全地执行。

**可管理性的关键方面：**

* **声明式配置**——描述系统的期望状态，而不是指定如何达到该状态。Kubernetes 就是声明式配置的典型例子：你声明想要 3 个 Pod 副本，Kubernetes 会确保实际状态符合期望。

```yaml
# 声明式配置示例
apiVersion: apps/v1
kind: Deployment
metadata:
 name: catalog-service
spec:
 replicas: 3 # 声明期望的副本数
 selector:
 matchLabels:
 app: catalog-service
 template:
 spec:
 containers:
 - name: catalog-service
 image: catalog-service:latest
```

* **不可变基础设施**——一旦部署，就不修改服务器或容器。如果需要更新，就部署新的实例并替换旧的。这避免了配置漂移和"雪花服务器"问题。

* **持续交付**——通过自动化的构建、测试和部署流水线，快速、安全地将变更交付到生产环境。

* **配置外部化**——将配置与代码分离，可以在不同环境中使用相同的构建。Spring Boot 提供了多种外部化配置的方式（环境变量、配置服务器等）。

* **基础设施即代码**——使用代码定义和管理基础设施，而不是手动配置。这使得基础设施可以版本控制、审查和重复使用。

**Spring Boot 的可管理性支持：**

* **Actuator 端点**——提供健康检查、指标、环境信息等管理端点。

```yaml
# 启用 Actuator 端点
management:
 endpoints:
 web:
 exposure:
 include: health,info,metrics,prometheus
 endpoint:
 health:
 show-details: when-authorized
```

* **外部化配置**——通过 Spring Cloud Config、环境变量或命令行参数配置应用程序。

* **Profile 支持**——使用不同的 Profile 为不同环境提供不同的配置。

可管理性是云原生应用程序能够在生产环境中长期运行和演进的关键。没有良好的可管理性，即使技术上正确的系统也会因为运维成本过高而失败。
