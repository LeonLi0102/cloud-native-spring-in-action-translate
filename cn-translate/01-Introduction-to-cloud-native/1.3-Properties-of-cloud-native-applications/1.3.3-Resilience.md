### 1.3.3 弹性

弹性是云原生应用程序在面对故障时维持服务水平的能力。在分布式系统中，故障是不可避免的——服务器可能宕机、网络可能中断、依赖服务可能不可用。云原生应用程序需要能够优雅地处理这些故障，而不是完全失败。

**弹性的关键原则：**

* **故障隔离**——一个组件的故障不应该导致整个系统崩溃。
* **快速失败**——当检测到故障时，应该快速返回错误，而不是长时间等待。
* **优雅降级**——当部分功能不可用时，系统应该能够继续提供核心功能。
* **自动恢复**——系统应该能够自动从故障中恢复，无需人工干预。

**实现弹性的常见模式：**

* **断路器（Circuit Breaker）**——当调用失败率达到阈值时，断路器会打开，后续请求直接失败而不是继续调用失败的服务。这可以防止级联故障和资源耗尽。

```java
// 使用 Resilience4j 断路器
@CircuitBreaker(name = "userService", fallbackMethod = "fallbackGetUser")
public User getUser(Long userId) {
 return userClient.getUser(userId);
}

public User fallbackGetUser(Long userId, Exception e) {
 // 降级逻辑：返回缓存的用户或默认值
 return cachedUserService.getCachedUser(userId);
}
```

* **重试（Retry）**——当调用失败时，自动重试几次。需要设置合理的重试次数和间隔，避免无限重试。

* **超时（Timeout）**——为远程调用设置超时时间，避免长时间等待无响应的服务。

* **舱壁（Bulkhead）**——将资源隔离到不同的"舱壁"中，防止一个失败的服务耗尽所有资源。

* **限流（Rate Limiting）**——控制请求速率，防止系统过载。

**Kubernetes 中的弹性配置：**

```yaml
# Pod 重启策略
spec:
 restartPolicy: Always # 容器失败时自动重启
 
# 健康检查
livenessProbe:
 httpGet:
 path: /actuator/health/liveness
 port: 8080
 initialDelaySeconds: 30
 periodSeconds: 10
 
readinessProbe:
 httpGet:
 path: /actuator/health/readiness
 port: 8080
 initialDelaySeconds: 10
 periodSeconds: 5
```

弹性不是免费的，它需要额外的设计和实现工作。但在云原生环境中，这是必不可少的，因为故障是常态，而不是例外。
