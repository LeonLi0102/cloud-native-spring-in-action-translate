### 1.4.2 持续交付

持续交付（Continuous Delivery，CD）是一种软件开发实践，确保软件可以随时可靠地发布到生产环境。它通过自动化的构建、测试和部署流水线来实现。

**持续交付的核心原则：**

* **构建一次，到处部署**——相同的构建制品（artifact）应该能够在所有环境中运行，从开发到生产。
* **自动化流水线**——从代码提交到生产部署的整个过程应该是自动化的。
* **快速反馈**——每次变更都应该快速得到反馈，包括构建状态、测试结果和部署状态。
* **可随时发布**——代码库应该始终处于可发布状态，发布应该是低风险、可预测的。

**部署流水线阶段：**

```
提交阶段（Commit Stage）
 ↓ 编译、单元测试、代码分析
验收阶段（Acceptance Stage）
 ↓ 集成测试、端到端测试、性能测试
生产阶段（Production Stage）
 ↓ 蓝绿部署/金丝雀发布、监控
```

**Spring Boot 的持续交付实践：**

```groovy
// build.gradle - 定义构建流水线
plugins {
 id 'org.springframework.boot' version '3.1.0'
 id 'com.palantir.docker' version '0.33.0' // Docker 构建
}

// 定义多个环境的配置
spring.profiles.active = project.findProperty('profile') ?: 'dev'

// 构建 Docker 镜像
docker {
 name "${dockerRegistry}/${project.name}:${version}"
 copySpec.from(tasks.bootJar).into("build/libs/")
 buildArgs(['JAR_FILE': "${project.name}-${version}.jar"])
}
```

**持续交付 vs 持续部署：**

* **持续交付**——代码可以随时发布到生产环境，但需要人工批准才能发布。
* **持续部署**——代码通过所有测试后自动发布到生产环境，无需人工干预。

**GitHub Actions 实现持续交付：**

```yaml
# .github/workflows/cd.yml
name: Continuous Delivery
on:
 push:
 branches: [main]
jobs:
 deploy-production:
 needs: [test, build]
 runs-on: ubuntu-latest
 environment: production # 需要人工批准
 steps:
 - name: Deploy to production
 run: |
 kubectl apply -f k8s/production/
 kubectl rollout status deployment/catalog-service
```

持续交付是云原生开发的核心实践，它使得快速、安全地交付软件变更成为可能。
