### 6.1.2 使用 Dockerfile 创建镜像

按照 OCI 格式，您可以通过在称为 Dockerfile 的特殊文件中列出指令序列来定义容器镜像。它是一个脚本，作为包含构建所需镜像所有步骤的配方。

在 Dockerfile 中，每条指令以 Docker 特定语法的命令开头。然后您可以将熟悉的 shell 命令作为参数传递给指令，具体取决于您使用的基础镜像。格式如下：

```
INSTRUCTION arguments
```

让我们通过定义一个 Dockerfile 来实践，构建上一节提到的容器镜像，包含以下主要指令：

1. 使用 Ubuntu 作为基础镜像
2. 安装 Java 运行时环境
3. 运行 java --version 命令

创建一个 my-java-image 文件夹，并在其中创建一个名为 Dockerfile 的空文件（无扩展名）。

**代码清单 6.1 包含构建 OCI 镜像指令的 Dockerfile**

```dockerfile
FROM ubuntu:22.04

RUN apt-get update && apt-get install -y default-jre

ENTRYPOINT ["java", "--version"]
```

默认情况下，Docker 配置为使用 Docker Hub 查找和下载镜像。ubuntu:22.04 镜像就是来自那里。Docker Hub 是一个您可以免费使用的注册表（在特定速率限制内），安装 Docker 时会自动配置。

java --version 命令是执行容器的入口点。如果不指定任何入口点，容器将不会作为可执行文件运行。与虚拟机不同，容器旨在运行任务，而不是操作系统。事实上，当使用 docker run ubuntu 运行 Ubuntu 容器时，容器会立即退出，因为没有定义任务作为入口点，只有操作系统。

Dockerfile 中最常用的指令如表 6.1 所示。

**表 6.1 Dockerfile 中用于构建容器镜像的最常用指令**

| 指令 | 描述 | 示例 |
|------|------|------|
| FROM | 定义后续指令的基础镜像。必须是 Dockerfile 中的第一条指令。 | FROM ubuntu:22.04 |
| LABEL | 以键/值格式向镜像添加元数据。可以定义多条 LABEL 指令。 | LABEL version="1.2.1" |
| ARG | 定义用户可以在构建时传递的变量。可以定义多条 ARG 指令。 | ARG JAR_FILE |
| RUN | 在现有层之上的新层中执行作为参数传递的命令。可以定义多条 RUN 指令。 | RUN apt-get update && apt-get install -y default-jre |
| COPY | 从主机文件系统复制文件或目录到容器内的文件系统。 | COPY app-0.0.1-SNAPSHOT.jar app.jar |
| USER | 定义将运行所有后续指令和镜像本身（作为容器）的用户。 | USER sheldon |
| ENTRYPOINT | 定义将镜像作为容器运行时要执行的程序。只有最后一条 ENTRYPOINT 指令被考虑。 | ENTRYPOINT ["/bin/bash"] |
| CMD | 指定执行容器的默认值。如果定义了 ENTRYPOINT 指令，它们将作为参数传递。如果没有，它也应该包含一个可执行文件。只有最后一条 CMD 指令被考虑。 | CMD ["sleep", "10"] |

一旦您在 Dockerfile 中声明了创建容器镜像的规范，就可以使用 docker build 命令逐一运行所有指令，为每条指令产生一个新层。从 Dockerfile 到镜像再到容器的整个过程如图 6.4 所示。

![](../../assets/ch06/5.1.png)
**图 6.4 镜像从 Dockerfile 构建。Dockerfile 中的每条指令都会在镜像中产生有序的层序列。**

现在打开终端窗口，导航到包含 Dockerfile 的 my-java-image 文件夹，运行以下命令（不要忘记最后的点）：

```bash
$ docker build -t my-java-image:1.0.0 .
```

完成后，您可以使用 docker images 命令获取新创建镜像的详细信息：

```bash
$ docker images my-java-image

REPOSITORY    TAG       IMAGE ID       CREATED         SIZE
my-java-image 1.0.0     96d1f58857aa   6 seconds ago   549MB
```

分层方法使镜像构建非常高效。每个镜像层是前一个的增量，Docker 缓存所有层。如果您只更改其中一层并再次构建镜像，只有该层及后续层会被重新创建。

由于这个原因，建议您根据更改的可能性对层进行排序，优化镜像构建过程。将更常更改的指令放在 Dockerfile 的末尾。

容器镜像可以使用 docker run 命令运行，该命令启动一个容器并执行 Dockerfile 中描述的进程作为入口点：

```bash
$ docker run --rm my-java-image:1.0.0

openjdk 11.0.15 2022-04-19
OpenJDK Runtime Environment (build 11.0.15+10-Ubuntu-0ubuntu0.22.04.1)
OpenJDK 64-Bit Server VM (build 11.0.15+10-Ubuntu-0ubuntu0.22.04.1, mixed mode)
```

> 注意：运行上述命令时，您会看到 Ubuntu 22.04 中的默认 OpenJDK 是 Java 11，而不是我们在本书中使用的 17 版本。
