## 6.4 部署流水线：打包和发布

在第 3 章中，我们开始实现部署流水线以支持 Polar Bookshop 项目的持续交付。持续交付是一种整体工程方法，用于快速、可靠、安全地交付高质量软件。部署流水线是自动化从代码提交到可发布软件整个过程的主要模式。

### 6.4.1 在提交阶段构建发布候选

运行静态代码分析、编译、单元测试和集成测试后，是时候将应用程序打包为可执行工件并发布了。在我们的例子中，可执行工件是容器镜像，我们将发布到容器注册表。

持续交付的一个重要思想是您应该只构建一次工件。在提交阶段结束时，我们将生成一个容器镜像，可以在部署流水线的任何后续阶段中重用，直到生产环境。

### 6.4.2 使用 GitHub Actions 发布容器镜像

GitHub Actions 是一个引擎，您可以直接从 GitHub 仓库自动化软件工作流。工作流定义通常存储在 GitHub 仓库根目录的 .github/workflows 目录中。

在第 3 章中，我们开始为 Catalog Service 开发实现部署流水线提交阶段的工作流。现在让我们继续实现，添加更多步骤来打包和发布应用程序。

打开 Catalog Service 项目的提交阶段工作流定义（.github/workflows/commit-stage.yml），添加打包和发布步骤。

**代码清单 6.9 配置发布候选信息**

```yaml
name: Commit Stage

on: push

env:
  REGISTRY: ghcr.io
  IMAGE_NAME: <your_github_username>/catalog-service
  VERSION: latest

jobs:
  ...
```

**代码清单 6.10 使用 Buildpacks 将应用程序打包为 OCI 镜像**

```yaml
  package-and-publish:
    name: Package and Publish
    needs: build-and-test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - name: Checkout source code
        uses: actions/checkout@v3
      - name: Set up JDK 17
        uses: actions/setup-java@v3
        with:
          java-version: '17'
          distribution: 'temurin'
      - name: Build container image
        run: ./gradlew bootBuildImage
      - name: Log in to GitHub Container Registry
        run: echo ${{ secrets.GITHUB_TOKEN }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
      - name: Tag container image
        run: docker tag $IMAGE_NAME:latest $REGISTRY/$IMAGE_NAME:$VERSION
      - name: Publish container image
        run: docker push $REGISTRY/$IMAGE_NAME:$VERSION
```

通过这个工作流，每次推送到 main 分支时，应用程序将自动构建、测试、打包为容器镜像并发布到 GitHub Container Registry。
