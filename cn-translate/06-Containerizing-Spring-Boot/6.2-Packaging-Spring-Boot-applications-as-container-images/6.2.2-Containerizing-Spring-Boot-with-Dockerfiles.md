### 6.2.2 使用 Dockerfile 容器化 Spring Boot

云原生应用程序是自包含的。Spring Boot 允许您将应用程序打包为独立的 JAR，包含运行所需的一切（运行时环境除外）。这使得容器化非常直接，因为除了 JAR 工件之外，容器镜像中只需要操作系统和 JRE。本节将向您展示如何使用 Dockerfile 容器化 Catalog Service 应用程序。

首先，您需要确定要基于哪个镜像。您可以选择 Ubuntu 镜像（如我们之前所做），然后显式安装 JRE，或者选择已经提供 JRE 的基础镜像，这样更方便。所有主要的 OpenJDK 发行版都有相关的镜像在 Docker Hub 上可用。选择您喜欢的任意一个。在本例中，我将使用 Eclipse Temurin 17，这也是我到目前为止在本地使用的 OpenJDK 发行版。然后您需要将 Catalog Service 的 JAR 文件复制到镜像中。最后，声明容器执行的入口点为在 JRE 上运行应用程序的命令。

打开您的 Catalog Service 项目（catalog-service），在根文件夹中创建一个名为 Dockerfile 的空文件（无扩展名）。该文件将包含容器化应用程序的配方。

**代码清单 6.2 描述 Catalog Service 镜像的 Dockerfile**

```dockerfile
FROM eclipse-temurin:17
WORKDIR workspace
ARG JAR_FILE=build/libs/*.jar
COPY ${JAR_FILE} catalog-service.jar
ENTRYPOINT ["java", "-jar", "catalog-service.jar"]
```

此 Dockerfile 声明了一个 JAR_FILE 参数，可以在使用 docker build 命令创建镜像时指定。

在继续之前，您需要为 Catalog Service 应用程序构建 JAR 工件。打开终端窗口，导航到 Catalog Service 项目的根文件夹。首先，构建 JAR 工件：

```bash
$ ./gradlew clean bootJar
```

默认情况下，Dockerfile 脚本会从 Gradle 使用的路径位置复制应用程序的 JAR 文件：build/libs/。因此，如果您使用 Gradle，可以通过运行以下命令构建容器镜像：

```bash
$ docker build -t catalog-service .
```

如果您使用 Maven，可以使用以下命令将 Maven 使用的位置指定为构建参数（不要忘记最后的点）：

```bash
$ docker build --build-arg JAR_FILE=target/*.jar -t catalog-service .
```

无论哪种方式，您最终都会得到 Catalog Service 应用程序打包为容器镜像。由于我们没有指定任何版本，镜像将自动标记为 latest。让我们验证它是否工作。

还记得上一节提到的两个方面：端口转发和使用 Docker 内置 DNS 服务器。您可以通过在 docker run 命令中添加两个参数来处理它们：

* `-p 9001:9001` 会将容器内的 9001 端口（Catalog Service 暴露服务的端口）映射到您本地主机的 9001 端口。
* `--net catalog-network` 会将 Catalog Service 容器连接到您之前创建的 catalog-network，使其可以与 PostgreSQL 容器通信。

这还不够。在上一章中，我们将 Catalog Service 的 spring.datasource.url 属性设置为 jdbc:postgresql://localhost:5432/polardb_catalog。由于它指向 localhost，从容器内部将无法工作。您已经知道如何从外部配置 Spring Boot 应用程序而无需重新编译，对吧？一个环境变量就可以解决。我们需要覆盖 spring.datasource.url 属性并指定相同的 URL，将 localhost 替换为 PostgreSQL 容器名：polar-postgres。使用另一个环境变量，我们还可以启用 testdata Spring 配置文件以触发目录中测试数据的创建：

```bash
$ docker run -d \
 --name catalog-service \
 --net catalog-network \
 -p 9001:9001 \
 -e SPRING_DATASOURCE_URL=jdbc:postgresql://polar-postgres:5432/polardb_catalog \
 -e SPRING_PROFILES_ACTIVE=testdata \
 catalog-service
```

这个命令相当长，不是吗？不过我保证您不会使用 Docker CLI 太长时间。在本章后面，我将介绍 Docker Compose。

打开终端窗口，调用应用程序并验证其是否正常工作，就像第 5 章中所做的那样：

```bash
$ http :9001/books
```

完成后，记得删除两个容器：

```bash
$ docker rm -f catalog-service polar-postgres
```

您刚刚遵循的方法非常适合在开发环境中试验 Docker 和理解镜像的工作原理，但在构建生产级镜像之前，您需要考虑几个方面。这就是下一节的主题。
