### 6.2.3 为生产构建容器镜像

Dockerfile 入门可能一开始并不难，但构建生产级镜像可能具有挑战性。在本节中，您将看到如何改进上一节中构建的镜像。

#### 性能

构建容器镜像时，您应该考虑构建时和运行时的性能。OCI 镜像的分层架构支持在构建镜像时缓存和重用未更改的层。容器注册表按层存储镜像，因此当您拉取新版本时，只下载更改的层。

Spring Boot 提供了分层 JAR 功能来构建更高效的镜像。默认情况下，Spring Boot 应用程序打包为由以下层组成的 JAR 工件（从最低层开始）：

* **dependencies** — 所有添加到项目的主要依赖
* **spring-boot-loader** — Spring Boot 加载器组件使用的类
* **snapshot-dependencies** — 所有快照依赖
* **application** — 应用程序类和资源

这意味着当您添加新的 REST 端点时，只有 application 层需要重新构建，大大提高了效率。

#### 安全性

容器镜像的安全性是生产环境中的重要考虑因素。以下是几个最佳实践：

* **使用最小基础镜像** — 较小的镜像具有较小的攻击面
* **非 root 用户运行容器** — 使用 USER 指令指定非 root 用户
* **扫描漏洞** — 使用 Docker Scout 或 Trivy 等工具扫描镜像漏洞
* **不要存储密钥** — 使用环境变量或秘密管理服务，而不是在镜像中硬编码

#### 多阶段构建

Docker 提供了多阶段构建功能，可以显著减小最终镜像的大小。通过使用多个 FROM 指令，您可以在一个阶段构建应用程序，在另一个阶段仅包含运行时所需的内容：

```dockerfile
# 构建阶段
FROM eclipse-temurin:17 as builder
WORKDIR workspace
COPY . .
RUN ./gradlew clean bootJar

# 运行阶段
FROM eclipse-temurin:17
WORKDIR workspace
COPY --from=builder workspace/build/libs/*.jar catalog-service.jar
ENTRYPOINT ["java", "-jar", "catalog-service.jar"]
```

这种方法的优势在于最终镜像不包含构建工具和源代码，使其更小且更安全。
